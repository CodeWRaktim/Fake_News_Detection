# 🚀 Fake News Detection System: Workflow & Architecture

This document explains the end-to-end workflow of the Fake News Detection application, breaking down how the user interface, backend server, machine learning model, and database interact.

---

## 1. High-Level Architecture
The project follows a modern decoupled architecture:
*   **Frontend:** React + Vite, styled with Tailwind CSS v3 and Material UI.
*   **Backend:** Flask API (Python).
*   **Database:** SQLite (`users.db`) managed via SQLAlchemy.
*   **ML Pipeline:** Scikit-Learn (TF-IDF + Logistic Regression) with Explainable AI (LIME).

---

## 2. User Journey & Workflow

### Phase A: Authentication (Security)
1. **User Opens App:** The frontend checks local storage for a JWT (JSON Web Token).
2. **Registration/Login:** 
    * The user enters credentials on the frontend Auth page.
    * React sends a `POST /register` or `POST /login` request to the Flask backend.
    * **Backend action:** Uses `Bcrypt` to hash/verify the password against `users.db`. 
    * If successful, Flask issues a JWT and React stores it, redirecting the user to the Main Page.

### Phase B: Verification & ML Prediction
1. **Input Submission:** The logged-in user pastes a news article or headline and clicks "Verify".
2. **API Request:** React sends a `POST /predict` request to Flask, attaching the news text and the user's JWT in the Authorization header.
3. **Data Preprocessing:**
    * Flask intercepts the text and passes it to `clean_text()` (removes punctuation, converts to lowercase, removes stopwords using NLTK).
4. **Machine Learning Inference:**
    * The cleaned text is transformed into a numerical matrix using the pre-trained `tfidf_vectorizer.pkl`.
    * The `fake_news_model.pkl` (Logistic Regression model trained on ~130k articles) predicts whether it is Fake (0) or Real (1).
    * It also calculates the confidence percentage (e.g., 96.68%).
5. **Explainable AI (LIME):**
    * The `LimeTextExplainer` runs a quick simulation to find *why* the model made that choice. It identifies the top 6 words that influenced the prediction (e.g., words pushing towards "Fake" vs. "Real").
6. **Saving to History:**
    * The backend retrieves the User ID from the JWT.
    * It saves the text snippet, prediction, confidence score, and timestamp to the `History` table in `users.db`.
7. **Response:** Flask sends the prediction, confidence, LIME explanation, and user data back to React as a JSON object.

### Phase C: Results & User History
1. **Rendering Results:** React receives the JSON and dynamically updates the UI using `ResultCard.jsx`, showing the verdict and highlighted important words.
2. **Updating Sidebar:** The frontend automatically triggers a `GET /history` request.
3. **Displaying History:** React updates the left-hand `HistorySidebar` to show the newly saved prediction at the top of the list. If the user clicks a previous history item, it automatically reloads into the main input box.

---

## 3. The Machine Learning Training Workflow (`train_model.py`)
This is a separate offline process used to upgrade the AI's intelligence:
1. **Data Loading:** Merges three datasets (`Fake.csv`, `True.csv`, `WELFake_Dataset.csv`, and LIAR) into a single Pandas DataFrame of ~130,000 articles.
2. **Preprocessing:** Applies the `clean_text` function to every article.
3. **Vectorization:** Uses TF-IDF (`ngram_range=(1,2)`, 10,000 features) to convert the text into numerical values, allowing the model to recognize phrases, not just single words.
4. **Training:** Fits a Logistic Regression model on 80% of the data.
5. **Evaluation:** Tests the model on the remaining 20% to generate an accuracy score (currently ~96.68%).
6. **Exporting:** Uses `joblib` to save the trained model and vectorizer into the `models/` directory, ready to be loaded by the Flask backend.

## 4. Directory Structure Recap
*   `/backend` - Flask API, Auth routes, Prediction logic, and SQLite DB.
*   `/frontend` - React application, Context providers (Auth/Theme), and UI components.
*   `/models` - Saved `.pkl` artifacts generated by the ML pipeline.
*   `/data` - Raw CSV files used for training.
*   `train_model.py` - Offline script to retrain the ML model.
*   `Runner.md` - Command cheatsheet for launching the application.
